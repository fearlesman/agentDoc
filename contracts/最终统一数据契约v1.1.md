# 最终统一数据契约 v1.1

> 本文件是四人唯一可执行契约。旧版 `四人协作模块划分与数据契约.md` 仅供背景阅读，不得据此写代码。所有 JSON 根对象使用 `schema_version: "1.1"`。

## 1. 术语与缩写说明

为避免成员因缩写产生理解差异，本项目统一使用以下含义：

| 缩写/术语 | 中文含义 | 本项目中的含义 |
|---|---|---|
| PSAC | 软件合格审定计划 | Software Plans for Software Aspects of Certification，本项目的合格审定计划类文档 |
| SRS | 软件需求规格/标准 | Software Requirements Specification，本项目的软件需求标准类文档 |
| IR | 中间表示 | `ParsedDocument`，解析器输出、审查引擎消费的结构化文档数据 |
| API | 应用程序编程接口 | 前端、编排服务和解析/审查模块之间的接口 |
| REST | 表述性状态转移 | 本项目 HTTP API 的接口风格 |
| RBAC | 基于角色的访问控制 | 按 `admin/reviewer/viewer` 控制资源权限 |
| OCR | 光学字符识别 | 从扫描图片或扫描 PDF 中提取文字；不可用时必须返回明确错误 |
| MIME | 多用途互联网邮件扩展类型 | 上传文件的媒体类型，如 DOCX/PDF 对应的 MIME 类型 |
| SHA-256 | 安全哈希算法 256 位 | 文件和解析内容的完整性校验值 |
| UUID/ULID | 通用唯一标识符/按时间可排序唯一标识符 | 文档、任务、审查、证据等对象的 ID 格式 |
| DOCX/PDF/XLSX | Word 文档/PDF 文档/Excel 工作簿格式 | 上传文件和检查单的文件格式 |
| JSON | JavaScript 对象表示法 | API 请求、响应和 fixture 的数据格式 |
| AI | 人工智能 | 自动解析、匹配或审查产生的机器结论；必须与人工复核结论区分 |
| P95 | 第 95 百分位耗时 | 性能评测中 95% 请求不超过的耗时 |
| CI | 持续集成 | 自动执行 schema、单元测试、状态机和契约校验的流水线 |
| JSDoc | JavaScript/TypeScript 文档注释 | D 模块公开函数和接口的注释格式 |
| fixture | 固定测试样例 | 用于契约、接口和异常场景重复验证的 JSON 样例 |
| anchor | 定位锚点 | 可从解析结果回指原文位置的稳定标识 |

全文首次出现时使用“中文全称（英文缩写）”或直接参照本表；成员任务书可直接引用本表。

## 2. 统一开发环境约束

- 团队基线：Windows 11、Python 3.11、uv、FastAPI/Pydantic、Node.js 20 LTS、React/TypeScript/Vite、pnpm、Git。
- DOCX/PDF 解析验证和报告转换使用 LibreOffice；系统必须支持在受控内网环境运行，保密材料不得上传外部 API。
- 仓库提交 `pyproject.toml`、`uv.lock`、`package.json`、`pnpm-lock.yaml`、`.env.example`；不提交 `.venv/`、真实课题材料、上传文件和导出文件。
- 成员可自行决定本模块内部的数据库、任务队列、UI 组件、OCR 和测试实现，但必须满足本契约、fixtures、内网运行和端到端验收；内部选型不构成跨模块接口。

## 3. 全局规则

- JSON UTF-8；ID 用 UUID/ULID；时间为带时区 ISO-8601；枚举使用小写英文。
- 页码、段落号、行号从 1 开始；不可取得时为 `null`，禁止猜测。
- 任何资源都有 `owner_id`；角色为 `admin | reviewer | viewer`。
- 原始文件、解析 IR、规则版本、提示词/模型版本、AI 结果、复核事件和报告快照均不可覆盖，使用版本/追加事件。
- `summary` 由服务端从 findings 和有效复核快照重算；`Finding.item_id` 在同一 Review 中唯一。
- `summary.total` 必须等于 findings 数量；状态计数之和必须等于 total；`high_risk` 是 severity=high 且 effective_status 属于 failed/needs_review 的数量。
- 所有版本中的 Checklist 内容不可原地修改；发布后只能创建新 checklist_version。进行中的 Review 永远使用其启动时锁定的版本。

## 2. 枚举与状态机

```text
document_type: psac | srs | generic | unknown
file_type: docx | pdf
finding_status: passed | failed | needs_review | not_applicable | error
step_status: passed | failed | skipped | uncertain | error
severity: high | medium | low | info
review_decision: accepted | rejected | modified
job_type: parse | review | export
job_status: queued | running | succeeded | failed | cancelled
export_status: queued | running | succeeded | failed | cancelled
checklist_status: draft | published | retired
match_status: pending | awaiting_confirmation | confirmed | rejected
```

### Document

```text
uploaded → parsing → parsed → awaiting_confirmation → reviewing → completed
                                      ↘ failed
```

- 上传成功后为 `uploaded`；解析 Job 成功后原子地变为 `parsed`，并创建 `ChecklistMatch(awaiting_confirmation)`；
- 用户拒绝匹配时 Document 回到 `parsed`，可重新生成/确认 Match；用户取消审查时回到 `awaiting_confirmation`，不会删除已解析数据；
- 解析失败保持 `failed`，可在修复/重传后创建新解析 Job；原失败记录保留。

### Job / Review / Export

- `Job.status`：`queued → running → succeeded`，也可到 `failed/cancelled`；
- `Review.status`：`queued | running | completed | failed | cancelled`；审查 Job 成功时 Review 才能 `completed`；部分检查项执行失败时 Review 可 `completed`，但 `summary.error>0` 且 `partial_failure=true`；整体编排失败才为 `failed`；
- `Export.status`：`queued | running | succeeded | failed | cancelled`；导出不改变 Document 状态；
- 非法转换返回 `INVALID_STATE_TRANSITION`；重试只允许从 failed 创建新 Job；取消由服务端处理并记录审计；
- `progress` 为 0–100；Job 必须有 `stage`、`current_item_id`、`completed_items`、`total_items`、`partial_failure`；终态 progress 为 100（succeeded）或保持最后进度（failed/cancelled）。

### Checklist 版本

- `draft` 可编辑但不能用于审查；`published` 可用于新审查且内容不可变；`retired` 禁止新审查但历史 Review 仍可读取；
- 进行中的 Review 锁定 `checklist_id + checklist_version`，任何修改都必须创建新版本；
- 同一版本的 `item_id`、规则语义和适用文档类型不可原地修改。

## 4. 核心对象

### 3.1 Document / ParsedDocument

`Document` 必填：`document_id,file_name,file_type,file_size,sha256,storage_key,owner_id,created_by,status,created_at`；`document_type` 可在解析后确定。

`ParsedDocument` 必填：

```text
schema_version, document_id, document_version, parser_version,
document_type, title, page_count, sections, blocks, tables,
warnings, full_text_sha256
```

Location 固定为：

```json
{"section_id":"sec_4_2","page":4,"paragraph_index":42,"line_start":null,"line_end":null,"anchor":"sec_4_2/blk_0042","source_offset_start":1200,"source_offset_end":1220}
```

`anchor` 必须能由 `GET /documents/{id}/parsed` 回指，且源文件版本和 SHA-256 匹配。

### 3.2 Checklist / ChecklistMatch / CheckItem

样例包含 PSAC 10、SRS 10、通用 12，共 32 条；每次审查以用户确认的 `selected_item_ids` 为准。

`CheckItem`：`item_id,category,document_types,question,logic_version,severity_default,reference,steps`。

`Step`：`step_id,order,kind,requirement,keywords,required`，kind 为 `section_exists | content_check | table_check | cross_reference`。

`ChecklistMatch`：`match_id,document_id,document_version,candidates,selected_item_ids,status,confirmed_by,confirmed_at`。

状态：`pending | awaiting_confirmation | confirmed | rejected`。selected IDs 必须非空、去重、排序；未确认禁止审查。

### 3.3 Review / Finding / Evidence

`CreateReviewRequest`：

```json
{"schema_version":"1.1","document_id":"doc_1","document_version":1,"match_id":"match_1","selected_item_ids":["common_001","psac_001"],"confirmed_by":"user_1","idempotency_key":"..."}
```

Review 必须保存 `review_id,document_ref,match_id,selected_item_ids,checklist_ref,engine_ref,status,summary,findings`。

Finding 必填：

```text
finding_id,item_id,question,status,severity,confidence,step_results,
evidence,problem,expected,actual,suggestion,engine_trace_id,created_at
```

最终聚合规则：任何 required step 为 error → item error；required step failed → failed；证据不足或 confidence < 0.70 → needs_review；全部 required passed 且有正向证据 → passed；不适用必须由规则明确声明。

Evidence：

```json
{"evidence_id":"ev_1","kind":"quote","quote":"4.2 系统架构","location":{"section_id":"sec_4_2","page":4,"paragraph_index":42,"line_start":null,"line_end":null,"anchor":"sec_4_2/blk_0042"},"source_document_version":1,"source_sha256":"..."}
```

`kind`：`quote | absence | table_cell | cross_reference`。

- quote：必须有 quote、anchor、源版本/hash；
- absence：必须有 `scope`（扫描章节/块/表）、`query`、`not_found_condition`，不得伪造 quote；
- table_cell：增加 `table_id,row,column`；
- cross_reference：增加 `target_document_ref`。

通过项必须有正向证据；失败/待复核项必须有反向 quote 或结构化 absence 证据。

### 3.4 ReviewDecision

```json
{"decision_id":"dec_1","finding_id":"finding_1","reviewer_id":"user_1","decision":"modified","comment":"...","final_status":"failed","final_severity":"high","final_problem":"...","final_suggestion":"...","reviewed_at":"server_generated"}
```

- accepted=接受 AI 初判；rejected=否决 AI 初判，comment 必填；modified=改判，四个 final 字段必填。
- 仅 reviewer/admin 可复核；仅 failed/needs_review 可发起；comment 1–2000 字；并发使用 `If-Match`/版本号，过期返回 `STALE_VERSION`。
- 报告分别统计 AI 原判和 effective 最终结论。

### 3.5 Report / Export

`ExportRequest`：`review_id,format,include_evidence,include_ai_and_human_decisions,requested_by`；format=`json|docx|pdf`。

`ExportResult`：`export_id,report_id,review_id,report_version,template_version,status,media_type,file_size,file_sha256,download_expires_at,error`。

报告快照必须包含 AI 原判和全部 decision 事件，导出后不可变；下载需授权、过期、可撤销并写审计。

### 3.6 Dataset / Annotation / Metric

评测集必须保存：

```text
 dataset_id,dataset_version,document_id,document_sha256,case_id,
defect_type,severity,gold_item_id,gold_status,gold_evidence_locations,
annotator_id,annotation_version,injection_change_list,split
```

`split` 为 `acceptance` 或 `dev`，验收集与开发集隔离，防止数据泄漏。指标报告必须记录脚本命令、原始结果、分母/分子、阈值和时间：提取准确率、Top-3 召回、证据定位准确率、要素漏检率、不符合项发现率、高风险拦截率、意见格式完整率、P95/最大耗时。空集返回 `null` 并说明原因。

## 5. API 目录

所有接口带鉴权头 `Authorization`、`X-Request-ID`；统一响应：`{"request_id":"...","data":{},"error":null}`。

```text
POST /api/v1/documents                         multipart(file)
GET  /api/v1/documents/{id}
POST /api/v1/documents/{id}/parse              → Job
GET  /api/v1/documents/{id}/parsed
GET  /api/v1/documents/{id}/matches
POST /api/v1/documents/{id}/matches/confirm
POST /api/v1/reviews                           CreateReviewRequest → Job+review_id
GET  /api/v1/tasks/{task_id}
GET  /api/v1/reviews/{review_id}
GET  /api/v1/reviews/{review_id}/findings      cursor,status,severity
POST /api/v1/findings/{finding_id}/decision   ReviewDecision
POST /api/v1/reviews/{review_id}/exports       ExportRequest → Job+export_id
GET  /api/v1/exports/{export_id}
GET  /api/v1/exports/{export_id}/download
GET  /api/v1/history                           cursor,limit,name,status,time_from,time_to
```

上传约束：允许 DOCX/PDF，默认单文件 ≤50 MB，空文件拒绝；扩展名和 MIME 双校验；服务器计算 SHA-256；重复 SHA-256 返回已有文档或 `DUPLICATE_FILE`，策略由 C 固定并记录。

HTTP 错误映射：400 字段错误、401 `UNAUTHORIZED`、403 `FORBIDDEN`、404 `NOT_FOUND`、409 `IDEMPOTENCY_CONFLICT|STALE_VERSION|INVALID_STATE_TRANSITION|MATCH_NOT_CONFIRMED`、413 文件过大、415 `UNSUPPORTED_FORMAT`、422 `PARSE_FAILED|OCR_UNAVAILABLE|CHECKLIST_NOT_FOUND`、500 `EXPORT_FAILED`。错误含 `code,message,details,field_errors,retryable`。

分页统一 cursor；响应含 `items,next_cursor,total`；findings 使用 review 快照，审查完成后不可变。

## 6. RBAC / 审计 / 留存

`admin` 可管理全部资源；`reviewer` 可操作被授权文档；`viewer` 只读。跨 owner 访问一律 403。Audit action：`upload,parse,match_confirm,review_start,review_complete,decision,export,download,delete,restore`；记录 actor、target、owner、request_id、结果、失败原因、前后状态、created_at。日志不可篡改。

结业删除/归还必须覆盖原文件、IR、向量、缓存、导出、备份，并生成 `deletion_proof`；默认保留期限和清理命令写入 README。

## 7. Fixture 与 CI

必须有 `document_ir.json, checklist.json, checklist_match.json, review.json, job.json, decision.json, export.json, dataset_case.json` 及正常/解析失败/规则缺失/低置信度/导出失败/越权/过期下载 fixture。CI 校验 schema、枚举、ID、anchor、summary、状态机、RBAC 和报告快照。
